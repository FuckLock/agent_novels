## 一、产品概述

### 1.1 定位

Toonflow 是一个短剧创作平台，已完成剧本生成功能（CLI 三阶段）和 Web 可视化界面。本次需求的核心目标是**打通"剧本之后"到"视频生成"的完整制作流程**，让用户在 Web 界面上完成从资产管理到视频产出的全部操作。

### 1.2 核心问题

| 问题 | 影响 | 严重度 |
|------|------|--------|
| Tab 4（塑造）的批量润色和图片生成是假实现 | 用户点击按钮后只有模拟效果，无法真正产出资产 | 高 |
| Tab 5（制作工作台）只能展示已有文件，不能触发 AI 生成 | 制作流程断裂，必须回到 CLI 操作 | 高 |
| 缺少完整管线可视化 | 用户无法理解当前处于管线哪个阶段，不知道下一步该做什么 | 中 |
| Tab 3（剧本）的"提取资产"按钮是前端正则实现，不写 assets.json | 与管线流程不一致，误导用户以为已完成资产提取 | 中 |

### 1.3 目标用户

短剧创作者——已通过 Toonflow 完成剧本生成，现在需要将剧本转化为视频内容。用户不具备专业技术背景，期望通过对话式交互和可视化界面完成制作。

### 1.4 核心目标

1. **Tab 4 可用**：资产管理模块的 AI 润色和图片生成功能真实可用
2. **Tab 5 可用**：制作画布实现完整管线（A导演分析 → B资产 → C1规划 → C2分镜表 → C3提示词 → D视频），通过 Agent 对话驱动
3. **流程衔接**：从剧本管理（Tab 3）可直接进入制作流程，无缝衔接

## 三、功能模块定义

### 模块 1：Tab 4 资产管理完善（P0）

#### F1.1 批量润色提示词 — 真实 AI 实现（P0）

**现状**：`/api/projects/{name}/seedance/assets/batch-polish` 后端是假实现（拼接字符串模拟提示词生成）。

**目标**：调用真实 AI 模型，基于资产描述 + 美术模板生成结构化图片提示词。

**功能描述**：
- 用户在 Tab 4 选中若干资产后，点击"批量生成提示词"按钮
- 后端逐个调用 AI 模型，读取资产的 description 字段 + 对应美术模板（skills/art-styles/{style}/），生成 prompt 和 artStyle
- 角色资产额外提取 identityAnchor（3~5 个核心视觉关键词）
- 生成结果写入 assets.json 对应资产的 prompt / artStyle / identityAnchor 字段
- 前端通过轮询 polish-status 接口展示进度

**验收标准**：
1. 选中 5 个无提示词的资产，点击批量润色，每个资产在 10 秒内返回非空的 prompt 字段
2. 生成的 prompt 包含 [PROMPT] 和 [ARTSTYLE] 两部分
3. 角色资产的 identityAnchor 包含 3~5 个视觉关键词
4. 进度条实时更新，显示"已完成 N/M"
5. 失败的资产标记 promptState: 'failed'，不影响其他资产继续生成
6. 可选择不同 AI 模型进行润色（模型下拉框从设置页读取）

#### F1.2 批量生成图片 — 真实 AI 实现（P0）

**现状**：`/api/projects/{name}/seedance/assets/batch-generate` 后端是假实现（setTimeout 模拟）。

**目标**：调用真实图片生成 API，基于资产的 prompt 生成参考图。

**功能描述**：
- 用户选中已有提示词的资产，选择图片模型和分辨率，点击"批量生成图片"
- 后端逐个调用图片生成 API，提交任务后轮询结果
- 图片下载保存到 novels/{name}/seedance/images/{type}/{name}.png
- 更新 assets.json 对应资产的 state / imagePath / generatedAt 字段
- 任务记录写入 tasks.json

**验收标准**：
1. 选中 3 个已有提示词的资产，点击批量生成图片，任务提交成功
2. 进度条显示每个任务的状态（排队/生成中/成功/失败）
3. 成功的资产，卡片上显示生成的图片
4. 失败的资产标记 state: 'failed'，error 字段包含失败原因
5. 可选择不同图片模型和分辨率
6. 并发控制：最多 5 个图片生成任务并行

#### F1.3 单个资产的提示词编辑和图片重新生成（P1）

**功能描述**：
- 在资产详情抽屉中，用户可手动编辑 prompt 字段
- 编辑后可点击"重新生成图片"按钮，使用编辑后的提示词重新生成
- 支持选择不同模型/分辨率

**验收标准**：
1. 详情抽屉中可编辑 prompt 文本区域
2. "重新生成"按钮调用单个图片生成 API
3. 生成中状态下按钮 disabled，显示 loading

#### F1.4 从大纲提取弹窗保留（P2）

**说明**：Tab 4 现有的"从大纲提取"弹窗功能保留不变，作为用户手动补充资产的入口。该功能是**手动管理入口**，不属于主管线流程。

### 模块 2：Tab 5 制作画布新建（P0）

#### F2.1 画布 + 对话双栏布局（P0）

**目标**：参考 Toonflow-app 的制作界面和现有 Tab 2（创作工作台）的 Agent 对话模式，构建"管线画布 + Agent 对话"双栏布局。

**功能描述**：

**左侧画布区（约 60% 宽度）**：
- 顶部：集数下拉选择器（参考 Toonflow-app 左上角下拉框，如"《造化之门》EP01: 困境·牺牲·秘密"）
- 管线节点图：横向或纵向排列的节点流程图，展示完整管线
  ```
  A 导演分析 → B 资产管理 → C1 导演规划 → C2 分镜表 → C3 分镜提示词 → D 视频生成
  ```
- 每个节点显示三种状态：未开始（灰色）/ 进行中（紫色脉冲）/ 已完成（绿色勾）
- 点击已完成的节点可展开查看该阶段的产出内容（复用现有的展示组件）
- 点击未开始/进行中的节点，右侧对话面板自动聚焦到该阶段的上下文

**右侧对话面板（约 40% 宽度）**：
- 复用现有 ContentWorkbench 的对话交互模式
- 对话面板顶部显示当前所处阶段标签
- 支持 SSE 流式输出
- 模型选择器（支持 CLI 模式和 API 模式）
- Agent 能感知当前管线进度，自动检查前置条件

**验收标准**：
1. 双栏布局，左画布右对话，比例约 6:4
2. 管线节点图显示 A→B→C1→C2→C3→D 六个节点
3. 每个节点正确反映当前状态（通过检查 novels/ 目录中对应文件是否存在）
4. 点击已完成节点可展开查看产出
5. 对话面板可发送消息并收到 Agent 回复
6. 集数切换时，节点状态和对话上下文同步更新

#### F2.2 管线节点状态检测（P0）

**功能描述**：

系统通过检查 novels/{name}/seedance/ 目录下的文件来判断每个节点的状态：

| 节点 | 状态判断依据 |
|------|------------|
| A 导演分析 | ep{N}/01-director.md 文件存在 → 已完成 |
| B 资产管理 | assets.json 存在且有 state:'success' 的资产 → 已完成 |
| C1 导演规划 | ep{N}/director-plan.json 文件存在 → 已完成 |
| C2 分镜表 | ep{N}/storyboard-table.json 文件存在 → 已完成 |
| C3 分镜提示词 | ep{N}/02-prompts.md 文件存在 → 已完成 |
| D 视频生成 | ep{N}/videos/ 目录下有 .mp4 文件 → 已完成 |

**验收标准**：
1. 节点状态实时反映文件系统状态
2. 进入 Tab 5 时自动检测一次
3. 每次 Agent 完成一个阶段后自动刷新状态

#### F2.3 Agent 对话驱动制作流程（P0）

**功能描述**：

右侧对话面板连接一个 productionAgent，该 Agent 能够：

1. **感知管线状态**：知道当前每个节点的完成情况
2. **引导用户**：根据管线状态，告知用户下一步应该做什么
3. **执行阶段任务**：
   - A 阶段：调用导演分析（director-skill）
   - B 阶段：导演分析完成后自动提取资产到 assets.json，触发提示词生成和图片生成
   - C1 阶段：调用导演规划（seedance-director-plan skill）
   - C2 阶段：调用分镜表构建（seedance-storyboard-table skill）
   - C3 阶段：调用分镜提示词生成（seedance-storyboard-skill）
   - D 阶段：调用视频生成（seedance-video skill）
4. **前置条件检查**：执行某阶段前自动检查前置条件是否满足，不满足时告知用户缺什么
5. **跨阶段跳转**：用户可说"跳到 Tab 4 调整资产"，Agent 引导跳转

**对话交互示例**：
```
Agent: 检测到第 1 集剧本已就绪。当前管线状态：
       - A 导演分析：未开始
       - B~D：未开始
       建议从导演分析开始。说"开始分析"即可启动。

用户: 开始分析

Agent: [流式输出导演分析过程]
       导演分析已完成，产出已保存至 ep01/01-director.md。
       已自动从导演分析中提取 5 个角色、3 个场景、2 个道具。
       下一步建议前往"塑造"Tab 检查资产，或说"继续"直接进入导演规划。

用户: 都生成吧

Agent: 好的，将按顺序执行：资产润色+生图 → 导演规划 → 分镜表 → 分镜提示词。
       [流式输出各阶段进度]
```

**验收标准**：
1. Agent 首次进入时自动汇报管线状态
2. Agent 能正确识别"开始分析"、"继续"、"都生成吧"等意图
3. 各阶段任务实际调用后端 API，产出写入 novels/ 目录
4. 前置条件不满足时 Agent 明确告知缺什么
5. 执行过程中左侧管线节点状态实时更新

## 四、关键用户流程

### 流程 1：从剧本到视频的完整流程（主流程）

```
1. 用户在 Tab 3 查看已生成的剧本
2. 点击"开始制作" → 跳转 Tab 5
3. Agent 检测管线状态，提示"建议从导演分析开始"
4. 用户说"开始" → Agent 执行导演分析（A阶段）
5. 导演分析完成 → Agent 自动提取资产到 assets.json
6. Agent 提示"已提取 N 个资产，建议检查后继续"
7. 用户说"继续" → Agent 执行资产润色+生图（B阶段）
   └─ 或用户跳转 Tab 4 手动调整资产，再回来继续
8. Agent 执行导演规划（C1）→ 分镜表（C2）→ 提示词（C3）
9. 用户可在任意阶段暂停、查看产出、提出修改意见
10. 最终执行视频生成（D阶段）
```

### 流程 2：资产精细调整流程

```
1. 用户在 Tab 5 制作画布中，Agent 完成导演分析后提取了资产
2. 用户点击 B 节点或说"去塑造 Tab 看看"
3. 跳转 Tab 4，查看资产卡片
4. 用户选中若干资产，使用批量面板：
   a. 批量生成提示词（真实 AI 调用）
   b. 检查/编辑提示词
   c. 批量生成图片（真实 API 调用）
   d. 查看图片效果
5. 不满意的资产，在详情抽屉中修改提示词后重新生成
6. 调整完成，回到 Tab 5 继续管线
```

### 流程 3：一键全自动流程

```
1. 用户进入 Tab 5，说"全部自动生成"
2. Agent 按顺序执行 A→B→C1→C2→C3→D，每步完成后简要汇报
3. 用户可随时说"停"中断流程
4. 最终产出所有视频
```

## 六、产品约束与规范

### 6.1 数据约束

- **唯一数据源**：所有资产数据存储在 novels/{name}/seedance/assets.json，Web 端只读写此文件
- **数据路径**：API 使用 `path.join(process.cwd(), '..', 'novels')` 访问数据，禁止硬编码绝对路径
- **任务跟踪**：图片和视频生成任务记录在 novels/{name}/seedance/tasks.json
- **向后兼容**：assets.json 读取时需 fallback 旧版 manifest.json 格式

### 6.2 交互约束

- **非阻塞**：批量任务执行期间，用户可切换 Tab 查看其他内容
- **可中断**：所有 AI 生成任务支持用户主动取消
- **进度可见**：所有异步任务必须有进度反馈（进度条/状态文字）
- **错误友好**：失败任务显示明确错误原因，支持重试

### 6.3 AI 模型约束

- **模型可选**：所有 AI 步骤（润色/生图/对话/分析）均支持用户在设置页配置模型
- **使用时可切换**：批量操作面板和对话面板提供模型下拉选择
- **并发限制**：图片生成最多 5 并发，视频生成最多 3 并发

### 6.4 设计约束

- 遵循 `web/DESIGN_SPEC.md` 的全局视觉规范
- 主色调 purple-600，状态色复用设计规范
- 画布节点图使用简洁几何风格，不用复杂 3D 效果
