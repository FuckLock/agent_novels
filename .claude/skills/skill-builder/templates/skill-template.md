# Skill 骨架模板

新 Skill 必须包含 **9 要素维度**：必备 8 项 + 按需 1 项。

复制以下内容到 `$SKILLS_DIR/[skill-name]/SKILL.md`，替换所有 `[占位符]`。

> **此模板严格对应 skill-builder SKILL.md 里的 [9 要素维度]。两边字段必须对称（反模式规则第 11 条）。**

---

## 必备 8 项（任何 Skill 都必须有）

```markdown
---
name: [skill-name]
version: 1.0
description: [一句话：什么时候触发、做什么、产出什么]
depends_on: [前置 Skill 列表，如 ["product-spec-builder"]，无依赖填 []]
---

[任务与边界]
    做：
    - [具体做什么 1]
    - [具体做什么 2]

    不做：
    - [明确不做什么 1，如属于其他 Skill 的事]
    - [不做什么 2]

    完成标准：
    - [客观可验证的完成标准 1]
    - [客观可验证的完成标准 2]

[第一性原则]（优先级从高到低）
    1. [最高原则名]
       [一句话说明 + 边界]
    2. [次级原则名]
       [一句话说明]
    3. [次次级原则名]
       [一句话说明]

[依赖检测]
    必需（缺失则终止）：
    [1] [前置依赖名]
        检测：[如何检测，如 Glob "**/X.md"]
        失败话术（一字不改）：
          "[明确告诉用户缺什么，不指挥流程]"

    可选（缺失则降级）：
    - [可选依赖] → [降级处理方式]

[XXX 维度 / XXX 规则 / XXX 策略]
    根据 Skill 性质命名（至少一节，可多节）：
    - 重看维度的 Skill（审查/分析）→ [XXX 维度]
    - 重守规则的 Skill（编码/修复）→ [XXX 规则]
    - 重做策略的 Skill（对话/规划）→ [XXX 策略]

    [子节 1：具体的维度/规则/策略]
    [子节 2：另一个维度/规则/策略]

    （对话/分析型 Skill 的"信息充足度判断"嵌入此节作为子节，不独立成节）

[工作流程]
    第 1 步：[做什么]
        [具体操作 + 引用 [XXX 维度/规则/策略]]

    第 2 步：[做什么]
        [具体操作]

    第 N 步：[做什么]
        [具体操作]

[输出格式]
    [Skill 完成后产出什么。给出明确的模板/字段定义/产物说明]

    [示例：
    """
    ✅ [Skill 名] 已完成

    [字段 1]：[值]
    [字段 2]：[值]
    ...
    """]

[初始化]
    AI 被 /[skill-name] 调用时按顺序执行：

    1. 输出开场："[一句话开场，含 emoji]"

    2. 执行 [依赖检测]
       失败 → 按失败话术终止

    3. 进入 [工作流程] 第 1 步
```

## 按需 1 项（业务 Skill 必须，元 Skill 可选）

```markdown
[输出风格]
    语态：
    - [描述 Skill 说话的方式，如"工程师式简洁"/"医生诊断式"/"采访者引导式"]

    反例（明文禁止）：
    × "[反例句子，如'应该没问题'、'大致 OK']"
    ✓ "[正例句子，如具体的二元判定/证据链表达]"
```

---

## 按需扩展节（按 Skill 类型加，不是必须）

| Skill 类型 | 加什么节 | 加在哪 |
|---|---|---|
| 多模式（如有 init/iterate 两种模式）| `[多模式工作流程]` | 替代 [工作流程] 或作为子节 |
| 元 Skill（操作敏感，如改 settings.json）| `[确认后执行]` | [工作流程] 内的关键步骤前 |
| AI 容易跳过步骤的（如执行型编码）| `[反合理化清单]` | 知识层补充节 |
| 对话/分析型（需判断"信息够不够")| 把 `[信息充足度判断]` 嵌入 `[XXX 维度]` 作为子节 | 不独立成节 |
| 发布/部署类（出错要回退）| `[回退策略]` | 知识层补充节 |
| 开发类（Phase 化任务）| `[Phase 完成度判断]` | [工作流程] 内 |

## 反模式（创建时禁止 - 12 条）

| ❌ 禁止 | 正确做法 |
|---|---|
| `[文件结构]` 单文件凑数节 | 删（不要硬塞结构图）|
| `[技能]` 与 `[工作流程]` 重复 | 二选一，不重复 |
| `[启动检查]` 与 `[初始化]` 命名冲突 | 用 `[初始化]`，不要起新名 |
| `[提议格式]` + `[返回格式]` 拆两节 | 合并为 `[输出格式]` |
| `[信息充足度判断]` 独立节 | 嵌入维度作为子节 |
| 失败话术含 "请先 /xxx" | 失败话术只说"缺什么"，不指挥流程 |
| 流程末尾"接下来 /xxx" | 由主 Agent 路由，子 Skill 不引导 |
| `[Skill 边界外]` / `[调用上下文]` | 跨 Skill 协调写在 CLAUDE.md，不写在子 Skill |
| "联网优先" 做第一性原则 | 下沉到 `[条件性联网策略]` |
| `depends_on` 与 `[依赖检测]` 不同步 | 两边必须一致（生产-消费分离）|
| 模板字段 vs SKILL `[维度]` 不对称 | 模板严格按 SKILL 里的 `[9 要素维度]` 列字段 |
| 模板重复 SKILL 已定义的规则 | 模板只搭骨架，规则在 SKILL.md |

## 规范速查

| 项 | 规范 |
|----|------|
| Skill 名 | kebab-case（如 dev-planner、bug-fixer） |
| 目录 | `$SKILLS_DIR/[skill-name]/`（Claude Code 默认 `.claude/skills/`）|
| 主文件 | `SKILL.md` |
| 模板（如有） | `templates/` 子目录 |
| Section 标题 | `[标题]` 格式 |
| 内容缩进 | 4 空格 |
| frontmatter | `name + version + description + depends_on` |
| 语言 | 项目主语言（中/英/其他，跟随当前项目） |
