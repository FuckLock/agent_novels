## 完整示例

**本示例特点**：Desktop / 开发者向 / 深色主题 / 紧凑密度
**不同品类请参考调整**：
- 消费级 Mobile → 倾向浅色 + 宽松密度 + 插画引导
- 企业后台 → 倾向中性色 + 紧凑密度 + 表格驱动
- 创作工具 → 倾向黑白灰 + 宽松留白 + 功能即视觉

以下是「AI 聊天助手桌面端（Forge）」的 Design Brief 示例：

```markdown
## 基于信息
- 源 Spec：Product-Spec.md v1.0
- 生成日期：2026-04-18
- 聚焦：视觉方向

## 设计方向

### 情绪关键词
- **专业** — 面向开发者，不要花哨，信息传达清晰
- **沉稳** — 深色主题为主，长时间使用不疲劳
- **精致** — 细节考究但不过度设计

### 参考产品
| 参考产品 | 喜欢的方面 | 不喜欢的方面 |
|---------|-----------|-------------|
| Linear | 信息密度高但不杂乱，动画流畅 | 无 |
| Arc Browser | 侧边栏设计，色彩运用 | 有些功能隐藏太深 |
| Raycast | 快捷键驱动，极简但功能强 | 有时信息太少 |

### 反面参考
- 企业后台风格：不要 Element UI / Ant Design 那种千篇一律
- 花哨动画：不要 Framer 官网那种满屏动效

### 目标用户审美
- 用户群体：开发者和技术用户
- 审美习惯：偏爱深色、极简、信息密集、快捷键驱动

## 视觉规范

### 色彩方向
- 主题模式：深色为主，支持浅色切换
- 色彩温度：冷色
- 品牌主色方向：深灰为底，靛蓝色作为品牌识别色
- 强调色方向：用于警告/重要操作，珊瑚色温暖且醒目

### 品牌资产
- Logo：有（极简几何）
- 已有品牌色：靛蓝色调 + 珊瑚色
- 字体：无指定，系统默认
- 吉祥物：有自定义 mascot 图标
- 整体品牌调性：专业、克制、有温度

### 信息密度
- 密度方向：偏紧凑
- 参考基准：接近 Linear
- 理由：产品多功能区（聊天/管理/设置），高效利用空间

### 排版方向
- 字体气质：几何无衬线，干净利落
- 中文字体：系统默认
- 标题风格：与正文差异适中

### 交互风格
- 动画程度：适中
- 过渡效果：快速渐变为主，不要弹跳
- 整体节奏：沉稳但不迟钝

## 核心页面视觉备注

### 聊天界面
- 核心交互：流式回复 + 工具调用展示
- 视觉方向：偏 Claude/ChatGPT 的对话布局，支持 Markdown
- 特殊要求：工具调用可折叠，不占满屏

### 管理面板
- 核心交互：三栏布局（分类导航 + 列表 + 编辑器）
- 视觉方向：偏 VS Code 的面板风格
- 特殊要求：编辑器支持代码高亮

### 侧边栏导航
- 核心交互：图标导航 + Workspace 切换
- 视觉方向：偏 Slack 的侧边栏，可折叠
- 特殊要求：折叠后只显示图标

## 状态设计
- 空状态：简短文案引导 + 操作按钮
- 加载状态：AI 回复用打字机光标，其他用骨架屏
- 错误状态：内联错误提示，珊瑚色边框
```

## 写作要点

## 写作要点

1. **情绪关键词**：最多 3 个，每个要解释在本产品中的具体含义
2. **参考产品**：必须标注"具体喜欢哪里"，不能只写产品名
3. **色彩方向**：写方向不写具体值（"蓝紫色调"而非"#6366F1"）
4. **信息密度**：必须附带参考基准（"像 XX 的密度"）
5. **核心页面备注**：只写有设计决策空间的页面，纯后端功能不写
6. **状态设计**：空、加载、错误三种状态都要有方向
7. **[待补充] 规则**：
   - 尽量探明的字段用户未提供 → 填为 "[待补充 - 原因]"，不留空
   - 必须探明的字段不允许 [待补充]（信息不够不出 Brief）
   - 下游看到 [待补充] → 提醒用户补齐再画设计稿
8. **字段与 SKILL.md 对应**：本模板字段严格对应 SKILL.md [采访维度]，填充顺序按采访顺序
9. **整体原则**：给设计工具和 dev-builder 看的，具体到能执行，但不到像素级
10. **产品基础信息不重复**：产品名/类型/目标用户/功能 见 Product-Spec.md，Brief 只聚焦视觉
