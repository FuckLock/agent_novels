# 变更记录模板

本模板用于记录 Product Spec 的迭代变更历史。
- 配套 SKILL：product-spec-builder（仅迭代模式触发）
- 用法：追加式（每次迭代追加一条新版本到文件最上面）

---

## 文件命名

`Product-Spec-CHANGELOG.md`（与 Product-Spec.md 同目录，通常在项目根目录）

---

## 模板格式

```markdown
# 变更记录

## [v1.2] - YYYY-MM-DD
### 新增
- 🔴/🟡/🟢 [变更内容]（位置：[Spec 章节]）—— 原因：[如有]

### 修改
- 🔴/🟡/🟢 [变更内容]（位置：[Spec 章节]）—— 原因：[如有]

### 删除
- 🔴/🟡/🟢 [变更内容]（位置：[Spec 章节]）—— 原因：[如有]

---

## [v1.1] - YYYY-MM-DD
### 新增
- ...

---

## [v1.0] - YYYY-MM-DD
- 初始版本（基于 Product-Spec.md v1.0）
```

[变更深度标记]
- 🔴 重度：涉及新 AI / 核心路径 / 布局结构 / 主要功能
- 🟡 中度：新增非核心 / 现有功能调整 / 局部布局
- 🟢 轻度：改文字 / 选项 / 样式

## 记录规则

【版本号规则】
- 常规迭代 +0.1（如 v1.0 → v1.1 → v1.2）
- 重大改版 +1.0（满足以下任一）：
  a) 整体重新定位（产品定义 / 目标用户 / 核心价值变了）
  b) 一次变更涉及 5+ 个功能
  c) 技术栈大改（如 Web → Desktop）

【日期】
- 使用当天日期，格式 YYYY-MM-DD（方便排序）

【变更描述】
- 从 product-spec-builder 的对话中提取
- 动词开头，简明扼要
- 标准格式：[深度标记] [变更内容]（位置：XX）—— 原因：YY（如有）
- 示例：
  - 用户说"加个 AI 推荐" → "🔴 新增 AI 一键推荐功能（位置：[功能需求]）"
  - 用户说"按钮放右下角" → "🟢 调整生成按钮位置到右下角（位置：[UI 布局]）"

【深度标记】
🔴 重度（满足任一即标）：
  a) 新增 / 移除 AI 能力
  b) 涉及核心用户路径变更
  c) 涉及布局结构（几栏、区域划分）
  d) 新增主要功能模块
🟡 中度：新增非核心 / 现有功能调整 / 局部布局
🟢 轻度：改文字 / 选项 / 样式

【分类】
- 新增 / 修改 / 删除
- 没有的分类不写

【内容粒度】
- 一条记录对应一个独立变更点
- 多个改动不混在一起

【追加位置】
- 新版本插入到文件最上面（倒序，最新在前）
- 不修改已有版本的内容（历史不可改）
- 错了 → 在新版本中标注"撤销 v1.X 的某改动"

【UI 变更】
- 新增控件要写位置（如"角色设定区底部"）
- 数值变更要前后对比（如"从 35% 改为 40%"）

【AI 能力变更】
- 新增或移除 AI 能力 → 必须单独记录（标 🔴 重度）

## 完整示例

**本示例特点**：消费级 Web 创作工具 / 3 个常规版本 + 1 个重大改版

以下是「剧本分镜生成器」的变更记录示例：


## 写作要点

1. **版本号**：常规 +0.1 / 重大 +1.0（按 [版本号规则] 判定）
2. **日期格式**：YYYY-MM-DD，方便排序
3. **变更描述**：动词开头 + 标准格式（[深度] [内容]（位置：XX）—— 原因：YY）
4. **深度标记**：必填，按 [深度标记] 规则判定
5. **位置引用**：必填，引用 Spec 中的章节名（如 [UI 布局]、[功能需求]）
6. **原因**：可选，但 🔴 重度变更建议必填
7. **分类原则**：
   - 新增：之前没有的
   - 修改：改变了现有内容
   - 删除：移除了之前有的
   - 没有的分类不写
8. **颗粒度**：一条 = 一个独立变更点，不合并多个
9. **追加方向**：新版本插入到文件最上面（倒序）
10. **历史不可改**：已记录的版本不修改，错了在新版本撤销
11. **AI 能力变更**：必须标 🔴 重度
12. **数值变更**：写前后对比（"从 X 改为 Y"）
