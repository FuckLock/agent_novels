AI **持续低估 CLAUDE.md 高频上下文成本，倾向写文档体而非运行时手册**。

模式演化轨迹：
- v4.2 / v4.3：**单段废话**——AI 把"看起来对未来 / 兼容 / 框架自身演化有用"的规则堆进 CLAUDE.md，缺"内容属性归类"前置门

第 1、2 次问题是「**塞错内容**」（非调用导向的也进了 CLAUDE.md），第 3 次问题是「**正确内容也写得太啰嗦**」（调用导向的内容写成文档体而非手册体）。共同根因：AI 把 CLAUDE.md 当"项目文档"在写，而不是当"主 Agent 每轮必读的运行时手册"在写。

## 教训建议

### 1. 【最高优先级】CLAUDE.md 内容硬性边界（白名单 / 黑名单）

**白名单（允许进入 CLAUDE.md）——agent skill 调用导向协调**：
- [角色] 主 Agent 身份与分工原则
- [任务] 主 Agent 独占工作 + 自检标准
- [全局原则] 跨 Skill 通用硬规则（注册表硬规则 / UI 优先级 / 语言 / 不偷懒）
- [Skill 注册表] / [Sub-Agent 注册表] 调用路由表
- [Hook 契约] Hook → 主 Agent 动作映射
- [路由优先级] 多入口冲突仲裁
- [项目旅程] 阶段 → 入口映射
- [跨 Skill / Hook 闭环] 多模块协作的硬流程
- [初始化流程] SessionStart 主 Agent 动作

**黑名单（一律不进 CLAUDE.md）**：
- 兼容性规则 / 别名映射 / 过渡期补丁 → PLAN.md 内部 / 弃用后清除
- 演化设计 / 选型准则 / 判定准则 → PLAN.md 或 skill-builder skill 内
- 历史注解 / 变更原因 / 版本演化说明 → PLAN.md / CHANGELOG
- 框架自评 / 反膨胀标准 / 三问规则 → 对应 skill SKILL.md 内
- 具体业务步骤 → 对应 skill SKILL.md 内

判断口诀：「**这条规则是主 Agent 每次会话路由时必须读到的吗？**」
- 是 → 白名单
- 否 → 黑名单（不管它看起来多有用）

### 2. CLAUDE.md 写入前的前置门（一句话硬规则）

> 任何向 CLAUDE.md 追加内容的动作前，先回答：「这条属于 agent skill 调用导向协调吗？」
> 不是 → 改放 PLAN.md / skill SKILL.md / CHANGELOG，**永远不进 CLAUDE.md**。

此规则应嵌入：
- skill-builder skill（生成新 skill / 框架修改时的前置 checklist）
- evolution-engine skill（生成 CLAUDE.md 修改提议时的前置过滤）
- 未来可能的 framework-editor skill（如果创建）

### 3. 给 CLAUDE.md / SKILL.md 等高频上下文文件新增内容前，跑"三问"（原 v4.2 保留）

每次会话都会重新加载 CLAUDE.md 与触发的 SKILL.md。新增任何段、规则、说明前，先问：

- **频率**：这条内容是否每次会话都需要被 AI 读到？
  - 是 → 进入下一问
  - 否（仅特定场景）→ 不该放进 CLAUDE.md，应放进对应 skill / 文档
- **可推理**：AI 在没有这条规则时能否从上下文推出正确行为？
  - 能推理 → 不该硬写，应让 AI 推理
  - 不能 → 进入下一问
- **成本**：这条内容的 token 成本 vs 它防御的错误代价，哪个大？
  - 成本大 → 不写
  - 价值大 → 写

仅当三问全部通过且属于"调用导向"白名单才该追加到 CLAUDE.md。

### 4. 兼容性补丁有"过渡期"概念，落地时必须分场景（原 v4.2 保留）

兼容性规则的本质是为"过渡期"服务的——过渡期一过就应该清除。落地时区分：

- **过渡期内**（重构进行时）：旧引用确实还存在，规则有价值 → 可写到 PLAN.md，**不写 CLAUDE.md**，必须标注"过渡期：X 月 X 日前"
- **过渡期结束**（重构完成后）：旧引用已全部清理，规则只有理论价值 → 一律清除

### 5. AI 的"过度防御 + 范围越权"双重倾向（v4.3 强化）

两次模式根源不是规则漏掉，是 AI 的两层惯性：

- **过度防御**：识别一个风险/可用性，本能反应是"加段保护"，不考虑代价
- **范围越权**：把"对框架未来 / 兼容 / 演化有用"和"对主 Agent 每次会话路由有用"混为一谈，默认都塞 CLAUDE.md

未来类似场景的提示词应明确：
- 识别风险 ≠ 必须打补丁
- 即使要打补丁，先问「这个补丁属于 CLAUDE.md 白名单吗」
- 不在白名单的，全部放 PLAN.md / skill / CHANGELOG

### 6. 【v4.4 新增 - 最高优先级】CLAUDE.md 写作风格硬规则（手册体 vs 文档体）

即使内容属于白名单，写作风格也必须遵循"手册体"——CLAUDE.md 是主 Agent 每轮必读的运行时手册，不是项目文档。

**手册体规范**：
- **索引式**：列条目 + 一行说明，不写完整段落
- **去重式**：同一规则只在一处出现，不在多段重申"不做 X / 不做 Y"
- **去使命化**：不写"使命 / 价值 / 存在意义"等元文案——CLAUDE.md 是给 AI 执行的，不是给人读的宣言
- **去注解化**：不写"为什么这么设计"——那是 PLAN.md 的事
- **格式硬约束**：表格优于文字描述；单行优于多行；缩写优于全称
- **欢迎语硬约束**：不写死多行欢迎语——临场组装一句即可

**文档体反模式**（必须避免）：
- 段首总有一句"使命：xxx / 价值：xxx"
- 多个相邻段都写一遍"不做 X / 不做 Y"（应只在一处集中）
- Hook 契约每条写 5 段（来源 / 能力 / 模式 / 动作 / 禁止）——只保留"动作 + 禁止"
- 注册表条目列 manual / auto 字段——主 Agent 用不上
- 用整段散文描述本可一行表格化的内容

判断口诀（每写一段后追问）：
> 「这段去掉一半字数后，主 Agent 还能正确路由吗？」
> 能 → 必须砍；不能 → 才保留
