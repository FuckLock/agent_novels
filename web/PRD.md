# Toonflow Web -- 产品需求文档（PRD）

> 版本：v2.1 | 更新时间：2026-04-15 | 创建时间：2026-04-10
> 本文档为 Toonflow Web 平台的产品需求定义，为设计师和开发者提供功能指导。

---

## 一、产品概述

### 定位

Toonflow Web 是短剧创作平台的可视化操作界面，读取 novels/ 数据，提供项目管理、剧本编辑、素材生成、制作工作台等功能。

### 目标用户

- 短剧创作者：需要将小说改编为短剧剧本
- 内容团队管理者：需要管理 AI 模型配置、监控生成流程

## 二、设置页面 -- 模型管理

### 2.1 页面目标

集中管理语言、视频、图像三类 AI 模型配置，让用户能快速完成模型的接入、切换和维护。

### 2.2 当前状态与问题分析

#### 现有功能

- 单一「模型管理」区域，包含语言模型、视频模型、图像模型三个卡片
- 语言模型支持 CLI/API 两种认证模式，通过分段控件切换
- 视频模型和图像模型各自全宽纵向排列
- 模型条目为固定宽度（w-48）的小卡片，hover 显示编辑/删除操作
- 新增/编辑通过 Modal 弹窗完成

#### 用户体验问题

**P0 -- 信息层级扁平，缺乏导航感**

- 三个模型区域纵向堆叠，视觉上无差异化，用户需要滚动才能定位目标区域
- 页面标题「设置」和副标题「管理 AI 模型配置」过于简单，无法传达页面的功能全景
- 「模型管理」作为唯一分区标题，与三个模型类型之间缺乏层级关系

**P0 -- 空间利用率低，布局单调**

- 三个卡片均为全宽排列，但内容通常只有 1-3 个模型条目，大量留白
- 视频模型和图像模型功能结构完全一致，但各占一个独立卡片，视觉冗余
- 模型条目卡片（w-48）尺寸固定，在宽屏上显得零散，在窄屏上又可能换行不美观

**P1 -- 交互反馈不足**

- 模型启用/禁用状态仅通过左边框颜色（绿色/灰色）和小圆点区分，辨识度低
- 编辑/删除按钮仅在 hover 时显示，移动端或触屏设备上不可发现
- 模型条目缺乏"当前正在使用"等上下文信息，用户无法知道哪个模型是活跃的

**P1 -- CLI 状态卡片与模型列表耦合**

- CLI 连接状态嵌套在语言模型卡片内部，语义上它是一个独立的系统状态信息
- 当用户切换到 API 标签页时，CLI 状态信息完全消失，失去连续性

**P2 -- 空状态引导薄弱**

- 空状态仅显示文字「暂无配置，点击 + 新增 添加」，缺乏视觉引导和操作提示
- 首次进入页面的用户无法理解三种模型分别用于什么场景

### 2.3 优化方向

> 以下为产品层面的功能方向定义，具体视觉方案由设计师决定。

#### 方向 A：左侧导航 + 右侧内容（推荐）

**核心思路**：将三类模型作为左侧导航项，右侧展示选中类型的模型列表和详情，减少滚动，提高空间利用率。

功能要求：
- 左侧纵向导航列出「语言模型」「视频模型」「图像模型」三个入口，每个入口旁显示已配置的模型数量
- 右侧内容区展示当前选中类型的完整信息：模型列表、新增入口、配置详情
- 语言模型的 CLI/API 切换保留在右侧内容区内
- CLI 连接状态提升为独立的全局状态指示器（如导航区域顶部），不随标签页切换消失

验收标准：
- 用户可通过左侧导航一键切换三种模型类型，无需滚动
- 任何模型类型下的已配置数量一目了然
- CLI 状态在所有视图下可见

#### 方向 B：统一表格视图

**核心思路**：将所有模型统一为一个表格/列表，通过筛选器区分类型，适合模型数量较多的场景。

功能要求：
- 顶部筛选栏：全部 / 语言模型 / 视频模型 / 图像模型
- 模型列表以行的形式展示，每行包含：模型名称、ID、类型标签、认证方式、启用状态、操作按钮
- 新增按钮在右上角，点击后根据当前筛选自动选中对应类型
- 支持搜索模型名称或 ID

验收标准：
- 所有模型在一个视图内可见，支持按类型筛选
- 每行信息密度适中，操作按钮始终可见（不依赖 hover）

#### 方向 C：卡片网格优化（最小改动）

**核心思路**：保留现有卡片堆叠结构，但优化卡片内部布局和信息展示。

功能要求：
- 视频模型和图像模型合并为一个「媒体模型」区域，用标签区分
- 模型条目改为响应式宽度，适配不同屏幕
- 操作按钮（编辑/删除）始终可见，不依赖 hover
- 为每个模型类型添加用途说明文字（如「用于剧本生成和对话」「用于视频片段合成」「用于角色立绘和场景图」）
- 空状态增加图标引导和快速配置入口

验收标准：
- 模型条目在不同屏幕宽度下均匀分布
- 操作按钮在任何设备上可发现、可点击
- 新用户通过用途说明能理解每种模型的作用

### 2.4 各方向通用的功能改进

无论选择哪个方向，以下改进均应纳入：

| 编号 | 改进项 | 优先级 | 说明 |
|------|--------|--------|------|
| S1 | 模型启用状态强化 | P0 | 启用/禁用状态需要更明确的视觉区分（不仅是边框颜色） |
| S2 | 操作按钮常驻可见 | P0 | 编辑和删除按钮不应仅在 hover 时出现 |
| S3 | 模型用途说明 | P1 | 在模型类型旁增加简短说明，帮助新用户理解每种模型的用途 |
| S4 | 空状态视觉引导 | P1 | 空状态增加插图/图标 + 分步引导文案 |
| S5 | CLI 状态全局化 | P1 | CLI 连接状态不应藏在语言模型的 CLI 子标签内 |
| S6 | 模型测试连接 | P2 | 提供「测试连接」按钮，验证 API 配置是否有效 |
| S7 | 响应式模型卡片 | P2 | 模型条目宽度自适应，而非固定 w-48 |

### 2.5 关键用户流程

#### 流程 1：首次配置模型

```
进入设置页 → 看到空状态引导 → 理解三种模型用途
    → 选择「语言模型」→ 点击新增 → 选择 CLI 或 API 模式
    → 填写配置信息 → 保存 → 看到模型出现在列表中
    → 继续配置视频模型和图像模型
```

#### 流程 2：编辑现有模型

```
进入设置页 → 定位到目标模型（通过导航或筛选）
    → 点击编辑按钮 → 修改配置 → 保存
    → 确认修改生效
```

#### 流程 3：切换模型启用状态

```
进入设置页 → 找到目标模型
    → 切换启用/禁用 → 状态即时反馈
```

### 2.6 产品约束

- 数据源：所有模型配置读写 novels/ 目录下的 config 文件，通过 `/api/settings/models` 接口
- 三种模型类型（language/video/image）为固定分类，不支持用户自定义类型
- 语言模型的 CLI 模式依赖本地 Claude Code CLI 安装状态，非 Web 可控
- 页面不涉及模型的实际调用，仅管理配置信息

### 2.7 待澄清项

| 编号 | 问题 | 影响范围 |
|------|------|----------|
| Q1 | 用户倾向哪个优化方向（A/B/C）？ | 决定设计规范更新范围 |
| Q2 | 是否需要支持模型排序（拖拽调整优先级）？ | 影响模型条目的交互设计 |
| Q3 | 是否需要「默认模型」标记（标识各类型下优先使用的模型）？ | 影响模型条目信息展示 |
| Q4 | 未来是否会增加更多模型类型（如音频模型）？ | 影响导航结构的扩展性设计 |

## 三、剧本 Agent 工作台 -- 模型切换选择器

### 3.1 功能目标

让用户在剧本 Agent 工作台的聊天面板中，无需离开当前工作流，即可快速切换对话所使用的语言模型。

### 3.2 用户场景与痛点

#### 目标用户

- 配置了多个语言模型（如 deepseek、kimi-k2.5、claude 等）的创作者
- 希望针对不同任务（骨架生成 vs 剧本润色 vs 自由对话）选用不同模型的高级用户

#### 痛点

- **P0 -- 无法选择模型**：当前聊天面板发送消息时，用户无法指定使用哪个语言模型，系统默认行为对用户不透明
- **P1 -- 切换成本高**：如果想换模型，用户需要离开工作台、进入设置页修改配置、再回来继续对话，流程断裂严重
- **P1 -- 缺乏上下文感知**：用户在对话过程中无法看到当前正在使用的模型是哪个，缺乏信任感和控制感

### 3.3 功能定义

#### F1：模型选择下拉框（P0）

**位置**：聊天面板底部输入区域，位于设置图标与输入框之间（或输入框上方一行）。

**数据来源**：调用 `GET /api/settings/models` 获取 language 数组，仅展示 `enabled: true` 的语言模型。

**交互要求**：
- 默认收起状态，显示当前选中模型的名称（`name` 字段），文字紧凑不占过多空间
- 点击后展开下拉列表，列出所有已启用的语言模型
- 每个选项显示模型名称（`name`），可选显示认证模式标签（CLI / API）作为辅助信息
- 选中某个模型后下拉框收起，显示新选中的模型名称
- 选中状态在当前会话内持久保持，切换页面标签再回来不丢失

**验收标准**：
- 下拉框中列出的模型与设置页面中已启用的语言模型一一对应
- 切换模型后，后续发送的消息使用新选中的模型（通过请求参数传递 `modelId`）
- 当仅有一个语言模型时，下拉框仍显示该模型名称但可不展开（或展开后只有一项）
- 当没有任何已启用的语言模型时，显示提示文案（如「未配置模型」）并禁用发送按钮

#### F2：模型选择状态传递（P0）

**说明**：用户选中的模型 ID 需要随消息发送到后端。

**交互要求**：
- 发送消息时，请求体中附带 `modelId` 字段（当前选中模型的 `modelId`）
- ChatPanel 组件需要新增 `selectedModelId` 和 `onModelChange` 的 props 接口，由父组件 ContentWorkbench 管理状态
- 如果用户在对话中途切换模型，后续消息使用新模型，已有消息不受影响

**验收标准**：
- `POST /api/projects/[name]/chat` 请求体中包含 `modelId` 字段
- 父组件可控制和读取当前选中的模型

#### F3：默认模型选择逻辑（P1）

**说明**：页面加载时需要确定一个默认选中的模型。

**选择优先级**：
1. 如果存在上次会话使用的模型（可通过 localStorage 存储），优先使用
2. 否则，使用已启用语言模型列表中的第一个
3. 如果没有已启用的语言模型，显示空状态

**验收标准**：
- 刷新页面后，模型选择器恢复到上次选中的模型
- 如果上次选中的模型已被禁用或删除，自动回退到列表第一个

#### F4：模型列表实时性（P2）

**说明**：如果用户在另一个标签页修改了模型配置（新增/删除/启用/禁用），回到工作台时模型列表应能感知变化。

**交互要求**：
- 每次打开下拉框时重新请求模型列表（轻量级刷新），或在工作台 tab 获得焦点时刷新
- 如果当前选中的模型被删除/禁用，自动切换到第一个可用模型并给出提示

**验收标准**：
- 在设置页新增一个语言模型后，回到工作台打开下拉框能看到新模型

### 3.4 关键用户流程

#### 流程 1：对话中切换模型

```
用户正在与 AI 对话（使用 deepseek）
    → 点击输入框旁的模型选择器
    → 下拉列表展开，显示 deepseek（当前选中）、kimi-k2.5、claude-sonnet
    → 选择 kimi-k2.5
    → 下拉收起，显示「kimi-k2.5」
    → 输入下一条消息并发送
    → 该消息使用 kimi-k2.5 模型处理
```

#### 流程 2：无可用模型

```
用户首次进入工作台，尚未配置任何语言模型
    → 模型选择器显示「未配置模型」
    → 发送按钮禁用
    → 点击选择器区域，显示提示「请先在设置页面配置语言模型」
    → 用户前往设置页配置模型
    → 回到工作台，选择器自动加载并选中第一个模型
```

### 3.5 与现有组件的关系

| 组件 | 变更 |
|------|------|
| `ChatPanel.tsx` | 新增模型选择器 UI、新增 `selectedModelId` / `onModelChange` / `models` props |
| `ContentWorkbench.tsx` | 管理 selectedModelId 状态、请求模型列表、发送消息时附带 modelId |
| `POST /api/projects/[name]/chat` | 请求体新增可选字段 `modelId`，后端据此选择模型 |
| `GET /api/settings/models` | 无变更，复用现有接口 |

### 3.6 产品约束

- 模型选择器仅展示语言模型（`language` 类型），不展示视频和图像模型
- 仅展示 `enabled: true` 的模型，已禁用模型不出现在下拉列表中
- 模型选择器不负责模型的增删改，配置管理仍在设置页面完成
- 选择器的视觉风格需与聊天面板的输入区域协调，不能喧宾夺主

### 3.7 待澄清项

| 编号 | 问题 | 影响范围 |
|------|------|----------|
| Q5 | 模型选择器放在输入框的上方一行还是与设置图标同行？ | 影响输入区域的布局设计 |
| Q6 | 是否需要在消息气泡上标注该消息使用了哪个模型？ | 影响消息展示结构 |
| Q7 | 模型切换后是否需要清空上下文/新建会话，还是继续当前会话？ | 影响后端会话管理逻辑 |

## 四、剧本管理 -- 卡片列表与详情弹窗

### 4.1 功能目标

将现有的"集数 Tab 切换 + 全文展示"的剧本管理方式，升级为"卡片列表总览 + 详情弹窗编辑"的模式，同时引入剧本与资产（角色/场景/道具）的自动关联能力，让创作者在管理剧本的同时掌握每集涉及的资产全貌。

### 4.2 用户场景与痛点

#### 目标用户

- 短剧创作者：通过 AI 生成了多集剧本，需要在 Web 端查看、编辑、管理剧本内容
- 内容团队管理者：需要快速浏览各集剧本概况，了解每集涉及的角色/场景/道具以协调后续制作

#### 痛点

**P0 -- 无法总览所有剧本状态**

- 现有 ScriptsTab 采用集数 Tab 切换方式，同一时间只能看到一集内容
- 集数较多时（如 20 集以上），用户需要逐个点击才能了解全貌，效率极低
- Tab 上仅显示集数和截断的标题（8 字），信息密度不足

**P0 -- 剧本与资产完全脱节**

- 创作者编辑剧本时，无法直观看到这一集涉及了哪些角色、场景、道具
- 需要在剧本 Tab 和资产库 Tab 之间反复跳转，工作流断裂
- 剧本文本中其实隐含了结构化的资产信息（人物行、场景标题行、动作描写行），但系统未解析利用

**P1 -- 编辑体验简陋**

- 当前编辑模式是一个全文 textarea，缺乏剧本名称等元信息编辑能力
- 编辑和阅读在同一页面切换，无法边浏览列表边编辑某一集

### 4.3 功能定义

#### F1：剧本卡片列表（P0）

**说明**：替换现有的 EpisodeTabBar + ScriptContentCard 组合，以卡片网格方式展示所有分集剧本。

**数据来源**：复用现有 `GET /api/projects/[name]/scripts` 接口获取剧本列表，结合 `outline.json` 中的分集信息补充标题和摘要。

**卡片信息要求**：
- 集数编号：如"EP01"、"EP02"
- 剧本标题：从剧本文件第一行 `# ... EP01: xxx` 解析，或从 outline.json 的 `title` 字段获取
- 字数统计：调用现有 `countChars` 工具函数计算
- 场景数量：从剧本文本中统计场景标题行（匹配 `S\d+` 或 `\d+ .+ 日|夜/外|内` 格式）的数量
- 卡片状态指示：有内容 / 空（尚未生成）

**交互要求**：
- 卡片以网格排列，响应式适配（大屏 4 列，中屏 3 列，小屏 2 列）
- 点击卡片打开该集的剧本详情弹窗（F2）
- 保留现有的"导出"能力（可在卡片上或弹窗内提供）
- 保留现有的"审核剧本"入口（可在卡片上或弹窗内提供）

**验收标准**：
- 所有已生成的分集剧本以卡片形式展示，信息完整（集数、标题、字数、场景数）
- 卡片点击后正确打开对应集的详情弹窗
- 空状态（无任何剧本）保留引导提示

#### F2：剧本详情弹窗（P0）

**说明**：以 Modal 弹窗形式展示单集剧本的完整信息，支持编辑剧本名称和内容，并展示关联资产。

**弹窗结构**（从上到下）：

1. **顶部区域 -- 剧本名称**
   - 输入框展示剧本名称，如"《叶真的秘密》EP01: 废柴的秘密"
   - 默认为只读状态，点击后进入编辑状态
   - 编辑名称后，更新剧本文件第一行的标题

2. **中部区域 -- 剧本内容**
   - 大文本区域展示完整剧本内容
   - 默认为只读模式（带行号的格式化展示，复用现有 `renderScriptLine` 渲染逻辑）
   - 点击"编辑"按钮进入编辑模式（textarea），复用现有编辑逻辑
   - 底部显示字数统计

3. **底部区域 -- 关联资产**
   - 标题："关联资产"，旁边显示资产总数
   - 按类型分组展示：角色 / 场景 / 道具与服装
   - 每个资产以 Tag 标签形式展示（详见 F3）
   - 提供"+ 选择资产"按钮用于手动补充（详见 F4）

4. **弹窗底部按钮**
   - "取消"：关闭弹窗，丢弃未保存的编辑
   - "确认"：保存所有修改（剧本名称、内容、关联资产），关闭弹窗

**交互要求**：
- 弹窗宽度：占视口宽度约 70-80%，最大宽度不超过 900px
- 弹窗高度：内容区域可滚动，弹窗本身不超过视口高度的 90%
- 打开弹窗时加载剧本内容（复用 `GET /api/projects/[name]/scripts/[episode]`）
- 保存时调用 `PUT /api/projects/[name]/scripts/[episode]` 更新内容
- 关闭弹窗前，如有未保存的修改，弹出二次确认提示

**验收标准**：
- 弹窗正确展示剧本名称、完整内容、关联资产三个区域
- 剧本名称和内容均可编辑并成功保存
- 关闭时未保存修改会触发确认提示
- 弹窗内的字数统计与卡片上的一致

#### F3：关联资产 Tag 展示（P0）

**说明**：在剧本详情弹窗中，以 Tag 标签形式展示该集剧本关联的资产。

**Tag 分类与样式**：
- **角色 Tag**：紫色系（与现有 AssetsTab 的 `TYPE_TAG_COLORS.roles` 保持一致：`bg-purple-100 text-purple-700`）
- **场景 Tag**：蓝色系（`bg-blue-100 text-blue-700`）
- **道具/服装 Tag**：绿色系（`bg-green-100 text-green-700`）

**每个 Tag 包含**：
- 资产名称文字
- 删除按钮（x 图标），点击后移除该关联（仅从当前剧本的关联列表中移除，不删除资产本身）

**分组展示**：
- 按"角色"、"场景"、"道具与服装"三组排列
- 每组有小标题标识类型
- 同组内的 Tag 水平排列、自动换行

**验收标准**：
- Tag 颜色与资产类型一一对应，视觉可区分
- 点击 x 可移除 Tag，移除后列表即时更新
- Tag 数量较多时能正常换行，不溢出

#### F4：手动添加关联资产（P1）

**说明**：用户通过"+ 选择资产"按钮，从项目的 outline.json 资产数据中手动选择并关联资产到当前剧本。

**交互流程**：
1. 点击"+ 选择资产"按钮
2. 弹出资产选择面板（可以是下拉面板或小弹窗）
3. 面板内按类型分 Tab（角色/场景/道具）展示 outline.json 中定义的所有资产
4. 已关联的资产显示为选中状态（不可重复添加）
5. 点击某个资产将其添加到关联列表
6. 关闭面板后，新 Tag 即时出现在关联资产区域

**数据来源**：
- 角色列表：`outline.json` 各集的 `characters[].name`（去重合并）
- 场景列表：`outline.json` 各集的 `scenes[].name`（去重合并）
- 道具列表：`outline.json` 各集的 `props[].name`（去重合并）

**验收标准**：
- 选择面板展示项目所有可用资产
- 已关联资产显示选中标记，不可重复添加
- 选择后 Tag 即时出现在关联区域

#### F5：剧本文本资产自动提取（P1）

**说明**：系统在打开剧本详情弹窗时，自动解析剧本文本内容，提取其中涉及的角色、场景和道具信息，作为关联资产的初始值。

**提取规则**：

**角色提取**：
1. 匹配"人物："或"人物:"行，提取冒号后的所有人名（以中文顿号"、"或空格分隔）
   - 示例：`人物：叶真、赵虎、众杂役弟子若干` -> 提取"叶真"、"赵虎"
   - 过滤规则：去除"若干"、"等"、"众"等修饰词开头的非具名角色
2. 匹配台词行（格式：`名字：台词` 或 `名字:台词`），提取冒号前的角色名
   - 示例：`赵虎: 废柴也配在宗门晃悠？` -> 提取"赵虎"
   - 过滤规则：排除括号内的旁白提示（如"（攥紧拳头，低声）"不算角色名）
3. 角色去重：同一角色名只出现一次

**场景提取**：
1. 匹配场景标题行，支持两种格式：
   - 格式 A：`S数字 场景名 时间/内外` -- 如 `S01 齐云宗·山门广场 日/晴`
   - 格式 B：`数字 场景名 时间/内外` -- 如 `1 宗门广场 日/外`
2. 提取场景名部分（去掉编号和时间/内外标记）
   - 示例：`S01 齐云宗·山门广场 日/晴` -> "齐云宗·山门广场"
   - 示例：`1 宗门广场 日/外` -> "宗门广场"

**道具/服装提取**：
1. 从动作描写行（以"△"开头的行）中，匹配 outline.json 中已定义的道具名称
   - 即：以 outline.json 的 `props[].name` 作为关键词词典，在动作描写中做文本匹配
2. 如果 outline.json 中没有道具数据，则不自动提取道具（避免误提取普通名词）

**与 outline.json 的交叉验证**：
- 自动提取的角色/场景名，优先与 outline.json 中对应集（`episodeIndex`）的 `characters[].name` 和 `scenes[].name` 做匹配
- 如果 outline.json 中该集定义了某个角色/场景，但剧本文本中未提取到，仍建议关联（以 outline.json 为补充来源）
- 最终关联列表 = 文本提取结果 + outline.json 补充（去重）

**验收标准**：
- 打开弹窗时，关联资产区域自动填充提取结果，无需用户手动操作
- 提取的角色与剧本中"人物:"行和台词行的角色名一致
- 提取的场景与剧本中的场景标题行一致
- 道具提取不会出现大量误提取（仅匹配已知道具词典）

## 五、塑造模块 -- 资产管理

> v2.0 更新（2026-04-12）：新增左侧批量操作面板、卡片信息增强、批量生成提示词/图片流程、配色方案调整。参考 Toonflow-app 资产管理模块设计。

### 5.1 功能目标

将原有的"素材生成"（空占位）和"资产库"（简单图片网格）两个 Tab 合并为统一的"塑造"Tab，让用户在 Web 界面上完成角色、场景、道具视觉资产的**查看、创建、编辑、批量选择、批量生成提示词、批量生成图片**的完整工作流。

### 5.2 用户场景与痛点

#### 目标用户

- 使用 CLI 生成了角色/场景/道具资产的短剧创作者，需要在 Web 端查看和管理这些资产
- 正在项目初期规划阶段的创作者，需要从大纲中快速提取资产清单并进行编辑
- 需要批量为资产生成提示词和图片的用户，希望在 Web 端一站式完成而非频繁切换 CLI

#### 痛点

**P0 -- 功能割裂，入口混乱**

- "素材生成"Tab 完全为空占位（显示"即将开放"），"资产库"Tab 仅展示图片文件，两个 Tab 功能重叠且不完整
- 用户无法在一个地方完成"查看资产信息 + 编辑资产详情"的完整工作流

**P0 -- 资产信息展示不足**

- 现有 AssetsTab 仅展示图片缩略图和文件名，缺少资产的核心元数据（状态、描述、提示词、模型、分辨率等）
- 没有详情查看入口，用户无法深入了解单个资产的完整信息

**P0 -- 无法创建和编辑资产**

- 目前所有资产必须通过 CLI 创建，Web 端完全只读
- 用户无法手动新增资产、编辑描述或修改提示词

**P0 -- 缺少批量操作能力**（新增）

- 资产数量通常在 20-50 个，逐个操作效率极低
- 无法按条件快速选择一组资产（如"所有未生成提示词的"、"所有失败的"）
- 无法批量触发提示词生成和图片生成，必须依赖应用内制作流程

**P0 -- 配色与业界惯例不符**（新增）

- 当前类型配色（角色=紫色、场景=蓝色、道具=绿色）与 Toonflow-app 及业界常见方案不一致
- 用户在多工具间切换时会产生认知混乱

**P1 -- 缺少从大纲提取资产的能力**

- outline.json 中已包含每集的角色、场景、道具定义，但用户必须手动进入应用流程才能生成 assets.json
- 无一键提取功能，创作初期的资产建立效率低

### 5.3 Tab 合并方案

#### 变更说明

将项目详情页的 Tab 从 6 个减少为 5 个：

| 变更前 | 变更后 |
|--------|--------|
| 素材生成（`assets-gen`，空占位） | **删除** |
| 资产库（`assets-lib`，简单图片网格） | **删除** |
| -- | 新增：**塑造**（`assets`，统一资产管理） |

变更后的 Tab 列表：小说原文、剧本Agent、剧本管理、**塑造**、制作工作台

#### 数据源切换

- 现有 AssetsTab 读取文件系统中的图片文件列表（`getAssets()` 返回 `{type, name, path, mode}`）
- 新的塑造模块改为读取 `seedance/assets.json` 结构化数据（`getSeedanceAssets()` 返回 `SeedanceAsset[]`）
- 图片展示仍通过文件系统路径，但资产元数据（名称、描述、提示词、状态等）来自 assets.json

### 5.4 配色方案调整（F-调整）

**变更原因**：对齐 Toonflow-app 配色方案及业界惯例，降低用户跨工具认知成本。

| 道具（prop） | 绿色 `bg-green-100 text-green-700` | **紫色** | `bg-purple-100 text-purple-700` |

**影响范围**：所有使用类型标签颜色的位置（卡片标签、筛选 Tab 指示色、详情抽屉标签、批量操作面板图标）统一变更。

### 5.5 整体布局升级（F-调整）

**变更前**：顶部筛选栏 + 全宽卡片网格

**变更后**：左侧批量操作面板（固定宽度）+ 右侧卡片网格区域

### 5.6 P0 功能定义

#### F1：资产卡片网格 -- 增强版（P0）

**说明**：以卡片网格形式展示项目的所有视觉资产，卡片信息增强，支持批量选择。

**数据来源**：`GET /api/projects/[name]/seedance/assets`，返回 `SeedanceAsset[]` 数组。

**卡片信息展示**（增强后）：

1. **右上角复选框**（新增）
   - 默认隐藏，hover 卡片时显示
   - 勾选后常驻显示，卡片边框变为选中态高亮色
   - 勾选/取消勾选不触发详情抽屉
   - 点击卡片其他区域仍可打开详情抽屉

2. **缩略图区域**
   - 显示资产图片（`imagePath`），无图片时显示类型对应的占位图标
   - 无图片且 `state` 为 `pending` 时，显示"等待生成"文字占位（对齐 Toonflow-app）
   - 生成中显示加载动画覆盖层

3. **资产名称 + 提示词状态标签**（新增标签）
   - 名称：`name` 字段，单行截断
   - 提示词状态标签（紧跟名称之后）：
     - `prompt` 字段非空 → 绿色标签"已生成提示词"
     - `prompt` 字段为空 → 橙色标签"未生成提示词"
     - `promptState === 'generating'` → 蓝色标签"提示词生成中"（带动画）

4. **类型标签**
   - 角色（**橙色**）/ 场景（**绿色**）/ 道具（**紫色**），对应 `type` 字段（配色已调整）

5. **模型名称**（新增）
   - 显示 `modelId` 字段值（如 "nano-banana-2"）
   - 未设置时显示"未指定模型"灰色文字

6. **分辨率**（新增）
   - 显示 `resolution` 字段值（如 "2K"、"1K"）
   - 未设置时显示"未指定"灰色文字

7. **描述预览**
   - `description` 字段，最多显示两行，溢出截断

8. **图片生成状态**（调整，更醒目）
   - 不再用小圆点，改为完整状态标签
   - pending → 灰色标签"待生成"
   - generating → 蓝色标签"图片生成中"（带脉冲动画）
   - success → 绿色标签"已完成"
   - failed → 红色标签"生成失败"（可 hover 查看错误信息 tooltip）

**筛选功能**：
- 类型筛选移至左侧批量操作面板（见 F6），不再单独占顶部 Tab
- 顶部操作栏保留：新增资产按钮、从大纲提取按钮、搜索框（按名称搜索）

**布局**：
- 位于左侧批量操作面板右侧
- 响应式网格：根据可用宽度自适应 2-4 列
- 卡片圆角、带边框和阴影，hover 时阴影加深提示可点击

**验收标准**：
- 页面加载后正确展示 assets.json 中的所有资产

#### F2：资产详情抽屉（P0）

**说明**：点击资产卡片后，从右侧滑出详情抽屉，展示资产完整信息并支持编辑。

**触发方式**：点击资产卡片的非复选框区域。

**抽屉结构**（从上到下）：

1. **标题栏**
   - 资产名称（可编辑，点击后变为输入框）
   - 类型标签（角色/场景/道具，只读，使用新配色方案）
   - 关闭按钮（X 图标）

2. **图片预览区**
   - 大图展示资产图片
   - 无图片时显示"暂无图片"占位
   - 角色资产如果有多视角图片（正/侧/后），预留 Tab 切换能力（本期仅展示主图）

3. **元信息区**（只读展示）
   - 状态：`state` 字段，带状态标签

   - 生成时间：`generatedAt` 字段

4. **可编辑区**
   - 描述文本框：`description` 字段，多行文本输入，支持编辑
   - 视觉锚点：`identityAnchor` 数组（仅角色类型显示），以标签形式展示，支持增删
   - 提示词文本框：`prompt` 字段，多行文本输入，支持编辑

   - 分辨率选择下拉框：选择分辨率（数据来源同左侧面板 F6）

5. **底部操作栏**
   - 保存按钮：将编辑内容写回 assets.json
   - 删除按钮：删除当前资产（需二次确认）

**交互要求**：
- 抽屉宽度约占页面 40%~50%，带半透明遮罩
- 打开/关闭有滑动动画
- 编辑字段后，保存按钮高亮变为可点击状态
- 保存成功后显示成功提示，抽屉保持打开，卡片网格同步更新
- 删除操作弹出确认对话框，确认后关闭抽屉并从网格中移除

**验收标准**：
- 抽屉正确展示资产的所有字段信息
- 编辑名称、描述、提示词后保存，刷新页面数据持久化
- 角色类型的资产显示 identityAnchor 标签组，场景和道具类型不显示
- 失败状态的资产显示错误信息
- 删除资产后，卡片网格立即更新，不需要刷新页面

#### F5：从大纲提取资产（P0）

**验收标准**：
- 正确解析 outline.json 中所有集数的角色/场景/道具

- 提取后的资产 description 字段来自 outline 中的 description

- 提取过程中显示加载状态

#### F6：左侧批量操作面板（P0，新增）

**说明**：页面左侧固定面板，集成快捷选择、类型筛选、模型/分辨率配置和批量操作触发按钮，替代原有的顶部筛选 Tab。参考 Toonflow-app 批量操作面板设计。

**面板结构**（从上到下分区）：

**区域 1：快捷选择指令**

提供一组快捷按钮/链接，一键批量选择特定条件的资产：

| 快捷指令 | 选择逻辑 | 说明 |
|----------|---------|------|
| 全选提示词为空 | `prompt === ''` 或 `prompt === undefined` | 快速定位需要生成提示词的资产 |
| 全选未生成项 | `state === 'pending'` | 快速定位待图片生成的资产 |
| 全选已生成项 | `state === 'success'` | 便于查看/导出已完成资产 |
| 全选错误项 | `state === 'failed'` | 快速定位失败资产进行重试 |
| 反选 | 取消已选、选中未选 | 灵活调整选择范围 |
| 取消选择 | 清空所有选择 | 重置选择状态 |
| 批预览图片 | 新窗口/弹窗展示已选资产大图 | 快速浏览已生成的图片质量 |

**交互细节**：
- 每个快捷指令为一个可点击的文字按钮/链接，紧凑排列
- 点击后立即生效，卡片网格中对应资产的复选框自动勾选
- 快捷指令旁显示将被选中的数量（如"全选提示词为空 (12)"）

**区域 2：素材类型筛选**

- 三个复选框：人物（角色）/ 场景 / 道具
- 默认全部勾选
- 取消某类型的勾选后，卡片网格隐藏该类型资产，同时该类型不参与快捷选择和批量操作
- 每个类型旁显示数量（如"人物 (8)"）
- 类型文字使用对应的新配色（人物=橙色、场景=绿色、道具=紫色）

**区域 3：生成模型选择**

- 下拉框，数据来源：`GET /api/settings/models?type=image`（读取 `config/models/image/*.json`）
- 显示模型名称（如 "Nano Banana 图像生成"）
- 选中模型后，批量操作将使用该模型
- 默认选中第一个可用模型
- 如果没有可用模型，下拉框禁用，显示"请先在设置中配置图像模型"

**区域 4：分辨率选择**

- 下拉框，选项：1K / 2K / 4K
- 默认值：2K（与 banana.json 中的 defaultParams.size 一致）
- 选中分辨率后，批量操作将使用该分辨率

**区域 5：批量操作按钮**

- **批量生成提示词**按钮：
  - 按钮文案：`批量生成提示词 (N)`，N = 已选中且 prompt 为空的资产数量
  - 无可操作资产时按钮禁用
  - 点击后触发 F7 流程

- **批量生成图片**按钮：
  - 按钮文案：`批量生成图片 (N)`，N = 已选中且 prompt 非空且 state 非 success 的资产数量
  - 无可操作资产时按钮禁用
  - 点击后触发 F8 流程

- 两个按钮垂直排列，主色调突出

**面板底部信息**：
- 显示选择统计："已选 X / 共 Y 个资产"
- 正在生成中时显示进度："提示词生成中 3/12"或"图片生成中 2/8"

**验收标准**：
- 面板在大屏幕上始终可见，中小屏幕可折叠
- 所有快捷选择指令正确按条件选中资产
- 类型筛选实时过滤卡片网格
- 模型下拉框正确加载 `config/models/image/` 中的模型列表
- 选中资产数量统计始终准确
- 未选中任何资产时，批量操作按钮禁用

#### F7：批量生成提示词（P0，新增）

**说明**：将已选中资产的描述（description）通过语言模型转化为结构化图片生成提示词（prompt），写回 assets.json。对应 CLI 的 asset-polish skill 功能。

**前置条件**：
- 至少选中 1 个资产
- 被操作的资产需要 `prompt` 字段为空（已有提示词的资产跳过，或提示用户确认是否覆盖）

**提示词生成规则**（与 CLI asset-polish skill 一致）：
- 输入：资产的 `name`、`type`、`description`、`identityAnchor`（如有）
- 输出格式：`[PROMPT] 主提示词内容 [ARTSTYLE] 画风风格描述`
- 角色类型参考美术模板 `art_character.md`
- 场景类型参考美术模板 `art_scene.md`
- 道具类型参考美术模板 `art_prop.md`
- 衍生资产使用对应的衍生模板（`art_character_derivative.md` 等）

**交互流程**：
1. 用户在左侧面板点击"批量生成提示词"按钮
2. 弹出确认对话框：
   - 显示将处理的资产数量和列表（名称 + 类型）
   - 如果部分资产已有提示词，提示"X 个资产已有提示词，是否覆盖？"并提供"跳过已有"/"全部覆盖"选项
3. 确认后开始生成：
   - 所有待处理资产的 `promptState` 更新为 `generating`
   - 卡片上的提示词状态标签变为"提示词生成中"（蓝色 + 动画）
   - 左侧面板底部显示进度："提示词生成中 3/12"
4. 生成完成：
   - 成功的资产 `promptState` 更新为 `completed`，`prompt` 字段写入生成结果
   - 失败的资产 `promptState` 更新为 `failed`，记录错误信息
   - 弹出结果通知："成功 N 个，失败 M 个"
   - 失败资产可一键重试

**并发控制**：
- 提示词生成使用语言模型（LLM），默认并发数 3
- 前端通过轮询 API 获取生成状态

**验收标准**：
- 批量生成过程中，卡片实时显示各资产的提示词生成状态
- 生成完成后，卡片的提示词状态标签正确更新
- 部分失败不影响其他资产的生成
- 生成过程中用户仍可浏览和查看资产（非阻塞）
- 生成结果写入 assets.json 持久化

#### F8：批量生成图片（P0，新增）

**说明**：将已选中资产的提示词（prompt）通过图片生成模型 API 生成参考图，下载到本地并更新 assets.json。对应 CLI 的 asset-generate-image + asset-save skill 功能。

**前置条件**：
- 至少选中 1 个资产
- 被操作的资产需要 `prompt` 字段非空（无提示词的资产跳过并提示）
- 左侧面板已选择生成模型和分辨率

**图片生成流程**（与 CLI 流水线兼容）：

1. **提交阶段**：
   - 调用图片模型 API 提交生成任务
   - 每个资产对应一个独立任务
   - 并发控制：最多 5 个任务同时运行（与 CLI asset-batch skill 一致）
   - 每个任务记录到 `tasks.json`，状态为 `queued` → `submitted`

2. **轮询阶段**：
   - 前端定时轮询任务状态（建议间隔 3-5 秒）
   - 任务状态流转：`queued` → `submitted` → `running` → `success` / `failed`
   - 成功后获取图片 URL

3. **保存阶段**：
   - 下载图片到 `novels/{name}/seedance/images/{characters|scenes|props}/{asset-id}.png`
   - 更新 assets.json 中的 `imagePath`、`state`、`modelId`、`resolution`、`generatedAt` 字段
   - 更新 tasks.json 任务记录

4. **失败重试**：
   - 单个任务失败自动重试 2 次（与 CLI 一致）
   - 超过重试次数后标记为 `failed`，记录错误原因到 `error` 字段
   - 用户可手动对失败资产发起重试

**交互流程**：
1. 用户在左侧面板点击"批量生成图片"按钮
2. 弹出确认对话框：
   - 显示将处理的资产数量、使用的模型名称、分辨率
   - 如果部分资产已有图片（`state === 'success'`），提示"X 个资产已有图片，是否重新生成？"
   - 显示预估信息（如"预计耗时约 X 分钟"，按每张 30 秒估算）
3. 确认后开始生成：
   - 所有待处理资产的 `state` 更新为 `generating`
   - 卡片上显示"图片生成中"状态 + 进度指示
   - 左侧面板底部显示整体进度："图片生成中 2/8"
   - 每完成一张，对应卡片立即刷新显示生成的图片
4. 全部完成后：
   - 弹出结果通知："成功 N 个，失败 M 个"
   - 失败资产卡片显示"生成失败"红色标签，hover 可查看错误原因

**并发与性能**：
- 图片生成 API 并发上限 5（通过 p-limit 控制）
- 前端轮询间隔 3-5 秒，使用单个轮询请求批量查询所有进行中任务的状态
- 生成过程中禁止对同一资产重复提交（按钮对"生成中"资产禁用）

**验收标准**：
- 批量生成过程中，卡片实时显示各资产的图片生成状态
- 图片生成成功后，卡片立即显示生成的图片缩略图
- 并发数不超过 5
- 失败自动重试 2 次
- 生成结果正确写入 assets.json 和 tasks.json
- 图片文件正确保存到对应目录
- 生成过程中用户仍可浏览其他资产（非阻塞 UI）
- 页面刷新后可恢复生成状态（从 tasks.json 读取进行中的任务继续轮询）

## 六、C3 提示词页面 -- 资产图片预览

### 6.1 产品概述

- **功能名称**：C3 提示词资产引用缩略图预览
- **所属模块**：制作工作台 > Seedance > C3 提示词
- **核心问题**：提示词中引用的资产（角色、场景、道具）以纯文本 `@图N（素材表@图M-资产名）` 形式展示，用户无法直观看到每个引用对应的实际图片，难以快速验证资产映射是否正确
- **核心价值**：让用户在视频生成前，通过缩略图一眼确认每条提示词引用的资产是否正确，降低因映射错误导致的视频返工成本

### 6.2 用户分析

**用户画像**：短剧创作者，使用 Seedance 模块生成视频，需在视频生成前核实提示词与资产的映射关系。

**用户痛点**：

| 编号 | 痛点 | 严重程度 | 说明 |
|------|------|----------|------|
| 1 | @图N 编号是抽象的，必须记忆或反复对照素材表 | 高 | Track 合并后单条引用 4-6 个资产，心智负担翻倍 |
| 2 | 资产映射错误难以发现 | 高 | 纯文本下，@图2 映射错误不易察觉，会导致生成视频结果错误 |
| 3 | 括号内文字名称不如图片直观 | 中 | 文字"叶真"不如直接看到角色图有辨识力 |

**使用场景**：

1. **快速校验**：用户打开提示词页面，扫视某条提示词下方的资产缩略图行，2 秒内确认全部引用正确
2. **疑问核实**：用户发现某个缩略图看起来不对，悬停查看名称和类型，确认是否映射有误
3. **详情审查**：用户在提示词详情抽屉中，查看所有引用资产的较大缩略图和名称，做最终确认

### 6.7 数据源与映射规则

**提示词中的引用格式**（实际数据示例）：

```
@图1（素材表@图1-叶真），@图2（素材表@图2-叶天成），@图3（素材表@图3-米江雪），@图4（素材表@图5-山门外凉亭）
```

**映射规则**：
1. 从文本中匹配 `@图(\d+)（素材表@图\d+-(.+?)）` 模式
2. 提取出引用编号（如 `@图1`）和资产名称（如 `叶真`）
3. 在 assets 列表中按 name 字段匹配
4. 获取匹配资产的 imagePath、type 等信息
5. 构建 `@图N → { name, type, imagePath }` 的完整映射

**assets.json 中的关键字段**：

| 字段 | 说明 | 示例 |
|------|------|------|
| name | 资产名称，用于匹配 | `"叶真"` |
| type | 资产类型 | `"character"` / `"scene"` / `"prop"` |
| imagePath | 图片相对路径 | `"seedance/images/characters/叶真.png"` |
| state | 生成状态 | `"success"` / `"pending"` |

### 6.8 边缘场景处理

| 场景 | 预期行为 |
|------|----------|
| 资产在 assets.json 中但图片未生成（state !== "success"） | 缩略图位置显示灰色占位符图标 |
| 提示词引用的资产名在 assets.json 中找不到 | 显示带问号的占位符，Tooltip 提示"未找到资产：{名称}" |
| 提示词不引用任何资产 | 不显示资产缩略图行，卡片布局与当前一致 |
| 资产图片加载失败（网络或文件问题） | 显示 fallback 占位符 |
| 单条提示词引用超过 6 个资产 | 缩略图行允许换行显示，保持卡片宽度不变 |
| `@图N` 与 `@图片N` 格式在同一项目中混用 | 解析器同时支持两种格式 |
